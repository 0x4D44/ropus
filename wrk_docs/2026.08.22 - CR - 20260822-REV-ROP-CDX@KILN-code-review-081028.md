## Result

Five shipped defects were independently confirmed and filed. The highest risks are a reverse Ogg scan that can trust a CRC-valid page nested inside payload data, and a decode-output race that can truncate the input. The remaining defects break the promised dither algorithm, strict info validation, and logical-stream metadata isolation. No source file was changed.

## Not reported as defects

- **General concurrent multiplex support — held out of scope.** The signed product contract remains unclear. `ROP-BUG-KIL-00047` is limited to rejecting or correctly pairing cross-serial headers; it does not require decoding multiplexed audio.
- **Finite volume outside `0.0..=1.0` — refuted by signed design.** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-081028\wrk_docs\2026.04.19 - HLD - ropusplay-directory-loop-status-keyboard.md:289-291` deliberately clamps finite values. Current validation correctly rejects only non-finite inputs.
- **Directory-entry errors — refuted by signed design.** Best-effort playlist enumeration is recorded behavior; the `filter_map(Result::ok)` path is intentional.
- **Partly corrupt native tracks — held for existing policy work.** Skipping Symphonia packet decode errors is source-visible, but fail-versus-recovery remains an explicit policy choice under `ROP-REQ-FLUX-00059`.
- **Native physical EOF — unverified.** Static inspection cannot distinguish Symphonia's normal `UnexpectedEof` completion from a reachable truncated-container false success across supported formats.
- **Whole-track buffering, large metadata, resample copies, and status-line scan cost — deduplicated.** `ROP-REQ-FLUX-00058` already owns their bounded-resource acceptance criteria.
- **Forward malformed-page scan complexity — unverified.** The bytewise seek/read path is visible, but this pass did not establish that a supported command reaches it before another parser rejects the same input.
- **Encoder partial-output loss — refuted.** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-081028\ropus-tools-core\src\commands\encode.rs:103-176` uses a same-directory temporary and atomic publication.
- **Terminal restoration and raw output corruption — refuted.** The inspected playback guard preserves restoration errors, and binary stdout paths keep banners off stdout.
