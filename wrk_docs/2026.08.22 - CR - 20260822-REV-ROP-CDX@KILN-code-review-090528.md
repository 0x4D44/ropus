# Code review — `ropus/` codec core

## Scope and method

- **Area:** `ropus/`
- **Baseline:** Deltic-supplied fresh `origin/main` worktree at `3972b032d19cbf59b32873b8db4ee35c26b95cf6`. No fetch was performed under the review-pass contract.
- **Method:** static source review only. No code, build, test, application, benchmark, or exploratory harness ran.
- **Lenses:** correctness, security, performance/scale, reliability, maintainability, test coverage, and an independent devil's advocate.
- **Verification rule:** each reported defect was re-read in source and challenged adversarially. Plausible, duplicate, refuted, or contract-ambiguous claims were withheld.
- **Result:** five confirmed defects filed Open. No new Draft requirement met the conservative capture threshold.

## Confirmed defects

### High — packet and repacketizer lengths can exceed Rust slice bounds

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\decoder.rs:208` accepts a claimed `len` without checking it against `data.len()`, then parses from that claimed extent. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\repacketizer.rs:1035` carries the same contract through `OpusRepacketizer::cat`; `:1097` trusts `maxlen` rather than the destination length; and `:1359` through `:1510` slice packet buffers by caller-supplied lengths. A safe caller can cause a panic or obtain a successful parse whose declared payload exceeds the source slice.
- **Concrete fix:** validate every source and destination capacity before access, parse only a bounded subslice, and return `OPUS_BAD_ARG` or `OPUS_BUFFER_TOO_SMALL` for inconsistent pairs. Add short-slice/oversized-length boundary tests for parse, cat, output, pad, and unpad.
- **Effort:** Medium.
- **Tracked as:** `ROP-BUG-KIL-00049`.

### High — low-level codec methods trust PCM capacities and unbounded frame sizes

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\encoder.rs:634` and `:1695` index input from `frame_size * channels` without proving the PCM slice is large enough. The native path similarly treats `max_data_bytes` as authoritative. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\decoder.rs:1204` and `:1337` through `:1410` slice or index caller output without checking capacity; the i24 and float wrappers allocate scratch from the caller size first. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\encoder.rs:441` also validates frame sizes with unchecked `i32` multiplication. Direct safe low-level calls can panic, accept an overflowed size, or attempt an infallible oversized allocation.
- **Concrete fix:** use checked frame arithmetic, enforce codec maximums before allocation, validate PCM/output slices and declared byte capacity, and use bounded/fallible scratch storage. Add undersized input/output, exact-boundary, and oversized-frame tests.
- **Effort:** Medium to large.
- **Tracked as:** `ROP-BUG-KIL-00050`.

### High — extension generation trusts negative frame counts and short spans

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\repacketizer.rs:794` rejects only frame counts above `MAX_FRAMES`; a negative count is cast to `usize` at `:828` and drives fixed-array indexing. `:706` through `:755` read extension payloads according to the descriptor's `len` without checking `ext.data.len()`, while writes use the claimed output `len` rather than the actual slice capacity. Invalid safe inputs can panic after partially mutating the destination.
- **Concrete fix:** preflight `nb_frames` in `0..=MAX_FRAMES`, use checked length arithmetic, validate every payload span and output capacity before writing, and add negative-count, short-payload, and claimed-length tests.
- **Effort:** Small to medium.
- **Tracked as:** `ROP-BUG-KIL-00051`.

### Medium — the public FEC queue accepts short vectors and overflows capacity

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\decoder.rs:663` forwards every feature slice to `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\dnn\lpcnet.rs:2340`. That implementation slices the first 20 features without checking width and guards the fixed 104-entry queue only with `debug_assert!`. A short feature vector or the 105th queued vector panics.
- **Concrete fix:** expose a checked status result, validate the exact feature width and queue position before slicing, define overflow behavior, and cover short, exact, full, and over-capacity cases.
- **Effort:** Small.
- **Tracked as:** `ROP-BUG-KIL-00052`.

### Medium — DRED decoding trusts zero rates and mutable latent counts

- **Confidence:** High.
- **Evidence:** on the found-payload path, `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\dred.rs:116` through `:145` divides by `sampling_rate` without validation. `:159` through `:190` casts `nb_latents` to `usize` and slices fixed arrays, while `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\dnn\dred.rs:2366` exposes the count and stage as mutable public fields. A zero rate, or a negative/oversized count with stage 1, causes a safe-call panic.
- **Concrete fix:** validate supported positive sample rates, enforce the fixed latent-count range before casting or processing, return `OPUS_BAD_ARG`, and add zero-rate plus negative/oversized-state tests.
- **Effort:** Small.
- **Tracked as:** `ROP-BUG-KIL-00053`.

## Actionable review-only findings

### Medium test gap — FEC coverage lacks a decoded-audio oracle

- **Confidence:** High that the gap exists; no codec-output defect was established.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\property_tests_codec.rs:491` through `:532` checks the recovered sample count but not the recovered samples. Branch tests at `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\decoder.rs:4657`, `:4682`, and `:5035` discard results or accept broad outcomes.
- **Concrete fix:** add a deterministic FEC sequence with a C-reference or independently pinned sample oracle; assert that the recovered prior frame is neither zero nor the current frame.
- **Effort:** Medium.
- **Tracking decision:** CR only. This pass did not confirm wrong shipped output, and the work is a focused missing test rather than durable design debt.

### Medium test gap — packet properties derive expectations from the implementation under test

- **Confidence:** High that the oracle is self-referential; no current mapping error was established.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\property_tests_packet.rs:17` through `:69` derives frame count, samples per frame, and total samples from the same helpers before asserting their arithmetic relationship. Shared TOC mapping defects can remain green.
- **Concrete fix:** pin independent RFC/reference expectations for representative TOCs and exercise malformed/truncated payloads through the full packet parser.
- **Effort:** Small.
- **Tracking decision:** CR only. This is a focused oracle improvement, not a separate shipped defect or structural requirement.

### Low maintainability risk — decoder reset invariants are duplicated

- **Confidence:** High that the duplication exists; current behavior is aligned.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-090528\ropus\src\opus\decoder.rs:608` through `:630` and `:1611` through `:1634` reset overlapping top-level, SILK, CELT, and neural state independently. Closed `ROP-BUG-FLUX-00012` shows reset-path drift has caused a real defect before.
- **Concrete fix:** route both entry points through one private runtime-reset helper and retain one reset/reuse regression that dirties neural state first.
- **Effort:** Small.
- **Tracking decision:** CR only. The current paths agree, so a new Draft requirement would be disproportionate.

## Not reported (why)

- **Duplicate:** projection encode/decode allocation before frame-size clamping is already Open as `ROP-BUG-CRUCIBLE-00005`.
- **Duplicate design work:** unimplemented DRED PCM reconstruction and neural real-time allocation debt are already Draft requirements `ROP-REQ-FLUX-00014` and `ROP-REQ-FLUX-00015`.
- **Refuted:** the high-level `api::Encoder` and `api::Decoder` do validate ordinary input/output sizing. The confirmed capacity defect is limited to the separately public low-level `opus` surface.
- **Refuted:** extension parsing now validates its iterator and output spans; closed `ROP-BUG-FLUX-00013` covers that parser defect. The new record concerns generation and other packet/repacketizer boundaries.
- **Refuted:** embedded neural-weight absence and the empty-blob fallback are intentional fresh-checkout/crates.io behavior. Model loading also builds replacement submodels before committing them, so no partial model state was confirmed.
- **Refuted:** an `EncoderBuilder` frame-duration mismatch does not permit an oversized PCM read; `frame_size_select` rejects a requested duration larger than the supplied frame first.
- **Held as UNVERIFIED:** decoder metadata is updated before a later frame decode can fail, but this static pass did not establish a reachable error packet or the required post-error state contract.
- **Held as UNVERIFIED:** `opus_packet_get_nb_frames([0x03, 0x00])` returns zero while the full parser rejects that packet. The reference source needed to decide whether the shallow query intentionally mirrors C was unavailable, so this is not filed.
- **Held as contract-ambiguous:** three TOC query helpers index an empty slice. The prior review already noted that they mirror C helpers requiring one TOC byte; this pass established neither a compatible fallible return contract nor an in-repo empty caller.
- **Not promoted:** broad C-shaped functions, public low-level modules, fixed-point wrapping, and unchecked-indexing macros were not defects without a specific reachable invariant violation.
