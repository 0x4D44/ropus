# Code review — `ropusenc/`

## Outcome

This static, multi-lens pass reviewed `ropusenc/` at baseline `a463e758ea319935fe68e074880e8020effda697` and followed its execution seams into `ropus-tools-core/`. It confirmed three new Medium defects and linked four further observations to existing records. No Critical or High defect was confirmed.

The review covered correctness, security, performance and scale, reliability, maintainability, and test coverage. A separate devil's-advocate pass challenged every candidate. No application, codec, test, exploratory harness, or benchmark ran.

## Confirmed findings

### Medium — atomic replacement can weaken destination permissions

- **Confidence:** High
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropus-tools-core\src\commands\encode.rs:132` creates the temporary file with process-default permissions. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropus-tools-core\src\commands\encode.rs:164` publishes that temporary inode by replacement; the Unix implementation is at line 180.
- **Impact:** Re-encoding over an existing restricted file can replace Unix mode `0600` with the umask-derived mode, commonly `0644`. The equivalent Windows replacement can substitute a restrictive destination ACL with permissions inherited by the temporary file.
- **Concrete fix:** Snapshot and apply existing destination security metadata to the temporary file before publication. Define the policy for new files. Add Unix mode and Windows ACL oracles that also prove a failed encode preserves the original.
- **Effort:** Small to medium.
- **Tracked as:** `ROP-BUG-KIL-00056`, Atomic encode replacement can weaken destination permissions.

### Medium — malformed packets can flood or block diagnostics

- **Confidence:** High
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropus-tools-core\src\audio\decode.rs:248` catches each Opus decoder failure, prints a warning at line 254, and continues. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropusenc\src\main.rs:390` supplies `OutputPolicy`, but this decoder diagnostic bypasses it.
- **Impact:** An input containing many malformed nonempty packets can produce unbounded stderr output even under `--quiet`. If stderr is a pipe whose reader does not drain, the encoder can block once the pipe fills.
- **Concrete fix:** Route decoder diagnostics through a policy-aware sink. Cap or aggregate repeated packet failures and emit one final count. Add bounded-output and quiet-mode regressions.
- **Effort:** Small to medium.
- **Tracked as:** `ROP-BUG-KIL-00057`, Malformed packets can flood and block ropusenc diagnostics.

### Medium — closed progress pipes can panic and make output state ambiguous

- **Confidence:** High
- **Evidence:** Infallible banner writes occur at `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropusenc\src\main.rs:292`. The encode progress macro uses `println!` and `eprintln!` at `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropus-tools-core\src\commands\encode.rs:299`. Final status writes at line 544 occur after the output commit at line 540.
- **Impact:** Rust's standard output macros panic when a downstream pipe closes. An early closure can abort before commit and discard the temporary output. A closure after commit can return a panic status even though the destination was published.
- **Concrete fix:** Use fallible locked writers through the shared UI layer. Give `BrokenPipe` an explicit graceful policy. Add regression cases for closure before and after commit.
- **Effort:** Small.
- **Tracked as:** `ROP-BUG-KIL-00058`, Closed progress pipes can panic and abort or misreport encoding.

## Confirmed observations already tracked

- `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropusenc\src\main.rs:275` uses Clap's exiting parse path before repository terminal escaping applies. The locked Clap formatter interpolates rejected values and arguments without escaping terminal controls. `ROP-BUG-KIL-00054` already calls for one shared safe Clap entry point across every CLI, so this pass did not file a duplicate.
- `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropusenc\tests\cli.rs:100`, lines 143, 180, 216, 250, 327, 389, 462, and 499 wait for child processes without a deadline, kill path, or guaranteed reap. `ROP-BUG-KIL-00055` already tracks the same CLI-test supervision defect; its fix should cover `ropusenc` as well as `ropusdec`.
- The shared native decoder allocates and extends whole-track PCM before encoding. `ROP-REQ-FLUX-00058` already specifies a bounded streaming pipeline for encode, decode, and play, including memory oracles.
- Per-packet Opus decode allocation remains covered by Open bug `ROP-BUG-KIL-00038`. This pass found no separate `ropusenc` cause.

## Actionable report-only gaps

- **Strengthen CLI output oracles.** Several integration cases only assert the first `OggS` bytes, for example `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-120528\ropusenc\tests\cli.rs:108`. Parse the complete Ogg stream and assert a valid Opus header, tags, audio packets, EOS, and granule bounds. **Effort:** Small to medium.
- **Cover CLI-to-core mappings independently.** The parser tests exercise sentinel routing, but most encoding flags are not checked against the resulting `EncodeOptions`. Add a table-driven mapping oracle for bitrate mode, application, complexity, frame duration, signal, channel selection, metadata, serial, and picture path. **Effort:** Small.

These are test-quality improvements, not proven shipped defects. They remain in this report rather than the bug or requirements ledger.

## Not reported

- **Refuted:** The CLI's wide integer bitrate acceptance is not a missing validation bug. Core validation deliberately applies libopus-compatible `500..=750000 * channels` limits.
- **Refuted:** Opening the final destination only after decode is not itself unsafe. The atomic writer preserves existing contents on ordinary failures. Permission preservation is the narrower confirmed defect above.
- **Refuted:** Abrupt process termination can orphan the same-directory temporary file, but the claim depends on forced termination and lacks a demonstrated repository-specific failure contract.
- **Refuted:** Quiet routing, stdin/stdout sentinel handling, option boundaries, serial handling, metadata order, picture preflight, build provenance, VBR/CVBR/CBR mapping, and Ogg timeline calculations matched their stated contracts in the inspected paths.
- **Already covered:** Rejecting unsupported native channel counts only after whole-track decode is an efficiency consequence of the streaming architecture tracked in `ROP-REQ-FLUX-00058`, not a separate requirement.
