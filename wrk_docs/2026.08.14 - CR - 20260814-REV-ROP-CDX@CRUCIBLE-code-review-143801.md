## Confirmed defects

### Medium — allocation-failure reporting stops at the outer wrapper

- **Confidence:** High.
- **Evidence:** `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\encoder.rs:167` and `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\decoder.rs:211` construct core codec state before calling `capi::alloc::try_box`. Those constructors perform infallible nested allocations at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\ropus\src\opus\encoder.rs:1539` and `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\ropus\src\opus\decoder.rs:574`; multistream and projection constructors follow the same order. The failpoint at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\alloc.rs:56` instruments only CAPI helper allocations. Consequently, `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\lib.rs:182` proves outer staging but not constructor-wide fallibility.
- **Impact:** allocator exhaustion can still abort the process instead of returning `OPUS_ALLOC_FAIL`. This is residual behavior after closed `ROP-BUG-FLUX-00017`, whose verification overstated the reach of its failpoint tests.
- **Concrete fix:** provide fallible core constructors or one shared allocation seam; stage every nested allocation before publishing the handle; inject failures inside core construction and after partial multistream sub-handle creation.
- **Effort:** Large.
- **Tracked as:** `ROP-BUG-CRUCIBLE-00001`.

### Medium — frame-sized scratch buffers allocate before the codec clamp

- **Confidence:** High.
- **Evidence:** `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\ms_decoder.rs:441` allocates float-decode scratch from the raw caller `frame_size`; `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\ropus\src\opus\multistream.rs:2436` does the same for projection decode. Projection float encode adds another raw-size allocation at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\projection.rs:410` before frame selection in the core. The native multistream path clamps to 120 ms before scratch allocation at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\ropus\src\opus\multistream.rs:1819`; the [upstream Xiph decoder](https://raw.githubusercontent.com/xiph/opus/main/src/opus_multistream_decoder.c) follows that order too.
- **Impact:** a large positive frame capacity can trigger an infallible allocation and abort before the normal clamp or argument result. This is distinct from closed `ROP-BUG-FLUX-00009`, which covered negative-size casts only.
- **Concrete fix:** apply the codec maximum before every temporary allocation, use checked fallible allocation, and add 120-ms-boundary plus oversized PLC/float/projection tests.
- **Effort:** Medium.
- **Tracked as:** `ROP-BUG-CRUCIBLE-00005`.

### Medium — extension shims allocate directly from caller capacities

- **Confidence:** High for the allocation path; impact is limited by the development-only scope.
- **Evidence:** `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\extensions.rs:146`, `:260`, and `:325` use `vec!` or `Vec::with_capacity` from caller counts. `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\repacketizer.rs:308` repeats the pattern. Only negative counts are rejected, and `ffi_guard!` cannot catch allocator aborts. The [upstream Xiph extension implementation](https://raw.githubusercontent.com/xiph/opus/main/src/extensions.c) processes caller storage directly without this duplicate temporary allocation.
- **Impact:** a large nonnegative capacity can terminate the conformance process in shim-owned allocation instead of producing an Opus error.
- **Concrete fix:** bound counts by packet/output limits, allocate with `try_reserve_exact`, map failure to `OPUS_ALLOC_FAIL`, and add failpoint plus large-capacity cases.
- **Effort:** Medium.
- **Tracked as:** `ROP-BUG-CRUCIBLE-00004`.

### Low — projection decoder size accepts impossible stream counts

- **Confidence:** High.
- **Evidence:** `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\projection.rs:428` omits `streams <= 255` and `streams + coupled_streams <= 255`, although the vendored header states both constraints at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\tests\conformance\include\opus_projection.h:377`. `proj_dec_size_for` then performs unchecked `c_int` multiplication at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\projection.rs:56`. The matching multistream query validates the total at `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\ms_decoder.rs:177`.
- **Impact:** invalid configurations can receive positive, wrapped, negative, or build-dependent sizes before construction rejects them.
- **Concrete fix:** share constructor dimension validation, use checked arithmetic, and cover 255/256, total-channel, and overflow boundaries.
- **Effort:** Small.
- **Tracked as:** `ROP-BUG-CRUCIBLE-00002`.

### Low — encoder size queries ignore `mapping_family`

- **Confidence:** High.
- **Evidence:** `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\ms_encoder.rs:205` and `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\capi\src\projection.rs:221` discard `mapping_family`, while their constructors validate supported families and channel layouts. The [upstream multistream implementation](https://raw.githubusercontent.com/xiph/opus/main/src/opus_multistream_encoder.c) and [projection implementation](https://raw.githubusercontent.com/xiph/opus/main/src/opus_projection_encoder.c) derive the size from validated mapping data and return zero when it is invalid.
- **Impact:** unsupported families and impossible ambisonics channel layouts receive usable-looking sizes, then fail at create/init.
- **Concrete fix:** reuse pure constructor validation in both size queries and add unsupported-family plus ambisonics channel-shape boundaries.
- **Effort:** Small.
- **Tracked as:** `ROP-BUG-CRUCIBLE-00003`.

## Test coverage conclusions

- The allocation failpoint tests are useful outer-staging oracles, but their names and prior verification imply reach they do not have. `ROP-BUG-CRUCIBLE-00001` includes the missing inner-allocation oracle.
- `C:\worktrees\ropus\20260814-REV-ROP-CDX@CRUCIBLE-code-review-143801\tests\conformance\tests\projection.rs:36` only force-links size functions; it has no direct invalid-boundary assertions. `ROP-BUG-CRUCIBLE-00002` and `ROP-BUG-CRUCIBLE-00003` include those tests.
- Aggregate extension/decode conformance entry points do not directly cover the wrapper-specific capacity and oversized-frame branches. Their regression work is included in `ROP-BUG-CRUCIBLE-00004` and `ROP-BUG-CRUCIBLE-00005`, not filed as separate test debt.
