## Confirmed findings

### High — playback buffers unbounded decoded audio before producing sound

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropus-tools-core\src\commands\play.rs:197-245` finishes
  `decode_track` before constructing the sink. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropus-tools-core\src\audio\decode.rs:194-288`
  accumulates complete interleaved PCM and allocates a second vector while applying Opus
  start/end trimming. Memory and first-sound latency therefore scale with track duration; long
  inputs can consume GiBs or terminate the player before playback starts.
- **Concrete fix:** stream decoded, trimmed PCM through a bounded queue/source; give metadata
  and decoded duration explicit budgets; avoid the final full-vector copy.
- **Effort:** Large.
- **Tracking:** Existing Draft `ROP-REQ-FLUX-00058` explicitly owns bounded streaming,
  playback memory, startup latency, metadata budgets, and per-tick label work. No duplicate
  requirement was raised.

### Medium — CLI integration tests can wait forever

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropusplay\tests\cli.rs:23-27,56-60,100-108` uses
  `Command::output()` for every child. There is no deadline, termination path, or explicit
  reap after timeout; cpal enumeration or a driver/child regression can wedge the crate's test
  run indefinitely.
- **Concrete fix:** use one cross-platform bounded child helper, kill and reap on expiry, and
  prove the timeout path with a hanging helper child.
- **Effort:** Small to medium.
- **Tracking:** `ROP-BUG-KIL-00061`.

### Medium — parse errors bypass terminal-control escaping

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropusplay\src\main.rs:114-121` calls Clap `get_matches()`, which renders and
  exits before `prelude::run()` can escape terminal-facing text. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\Cargo.lock:266-275` pins
  `clap_builder` 4.6.0; `C:\Users\marti\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\clap_builder-4.6.0\src\error\mod.rs:461-470` stores the rejected value unchanged and

- **Concrete fix:** route every CLI through one `try_get_matches` entry point that preserves
  known styling while reversibly escaping attacker-controlled context strings.
- **Effort:** Medium.
- **Tracking:** Existing open `ROP-BUG-KIL-00054` already specifies the shared all-CLI fix;
  no duplicate was raised.

### Medium — shared decoder diagnostics can flood or break stderr

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropus-tools-core\src\audio\decode.rs:248-260` emits one infallible
  `eprintln!` for every rejected Opus packet. `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropus-tools-core\src\commands\play.rs:607-609`
  reaches this path without an output policy or fallible diagnostic sink. Malformed streams can
  produce unbounded logs, block on a pipe, or panic when stderr closes.
- **Concrete fix:** pass a fallible policy-aware diagnostic sink into shared decode, cap or
  aggregate repeated warnings, and report a final count.
- **Effort:** Medium.
- **Tracking:** Existing open `ROP-BUG-KIL-00057` owns this shared decoder defect; no duplicate
  was raised.

### Medium — the banner can panic when stdout closes

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropusplay\src\main.rs:127-133` calls
  `D:\worktrees\ropus\20260822-REV-ROP-CDX@KILN-code-review-133528\ropus-tools-core\src\ui.rs:14-18`, whose `println!` write is infallible. A downstream reader
  that closes stdout can turn ordinary playback startup into a panic status before the fallible
  playback writer takes over.
- **Concrete fix:** make shared banners use locked fallible writers and define BrokenPipe
  handling consistently across all CLI output.
- **Effort:** Small to medium.
- **Tracking:** Existing open `ROP-BUG-KIL-00058` already requires the shared-UI fallible
  writer fix; no duplicate was raised.
