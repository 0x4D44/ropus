## Outcome

This pass confirmed six defects: three High, two Medium, and one Low. The most
immediate failure is that the adapter accepts forward-only Opus streams and then
unconditionally seeks before decoding them, so live playback fails before its
first sample.

Seven independent roles reviewed the same slice: correctness, security,
performance/scale, reliability, maintainability, test coverage, and a dedicated
devil's advocate. Every finding below survived source-level adversarial checking.
The directly related `ropus-fb2k` source was read only to establish the adapter's
ABI and stream contracts; this pass does not claim full coverage of that area.

Bug filing is blocked by the review sandbox. `deltic bugs new` refused before
creating a file because it could not write the clone-wide reservation lock at
`C:\language\ropus\.git\deltic-ledger-mint.lock`. Hand-minting would violate the
ledger's collision-safety contract, so no unreserved bug IDs were fabricated.
The findings are bug-ready below, including title, severity, priority, fix, and
regression oracle.

## Confirmed findings

### CR-FOO-01 — High: unseekable streams fail during playback initialization

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\src\input_ropus_opus.cpp:172`,
  `:246`; contract at
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\ropus-fb2k\src\reader.rs:672`.
- **Evidence:** `open()` deliberately supplies no seek callback for a
  forward-only source. The Rust reader accepts that source and leaves its cursor
  at the first audio packet. The first `decode_initialize()` nevertheless calls
  `ropus_fb2k_seek(reader, 0)`. The backend explicitly rejects every seek when
  `file_size` is unknown. The signed HLD requires live HTTP playback at
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\wrk_docs\2026.04.18 - HLD - foobar2000 opus decoder component.md:599`.
- **Actual:** live HTTP, archive-backed, or other forward-only inputs can open,
  then throw `INVALID_STREAM` before the first `decode_run()`.
- **Concrete fix:** track whether initialization has occurred. Preserve the
  already-correct cursor on the first initialization of a non-rewindable reader;
  rewind seekable readers and define repeated initialization of forward-only
  readers explicitly.
- **Regression oracle:** use a forward-only in-memory `file`, open for decode,
  initialize once, and require the first run to return PCM. Then pin the chosen
  repeated-initialize behavior after one decoded chunk.
- **Effort:** Medium.
- **Tracking:** bug-ready title `Unseekable Opus streams fail during playback initialization`;
  proposed **Should / High**.

### CR-FOO-02 — High: tag callback exceptions can cross Rust FFI

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\src\input_ropus_opus.cpp:109`;
  callback invocation at
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\ropus-fb2k\src\lib.rs:373`.
- **Evidence:** every I/O callback catches C++ exceptions and marshals them via
  `IoCtx::pending`, but `tag_cb` calls copying and allocating `file_info`
  operations without an exception barrier. Rust invokes it as an `extern "C"`
  callback. A C++ allocation or SDK exception can therefore unwind through Rust
  frames; Rust's panic guard does not make foreign unwinding safe.
- **Actual:** metadata import can terminate the foobar2000 process or invoke
  undefined behavior instead of returning the original C++ error.
- **Concrete fix:** pass a `TagCtx` containing `file_info*` and an
  `exception_ptr`. Catch and retain the first exception inside `tag_cb`, make
  later callbacks no-op, return normally to Rust, then rethrow after
  `ropus_fb2k_read_tags()` returns, including when its status is zero.
- **Regression oracle:** inject a metadata sink that throws from first-value and
  duplicate-value insertion. Prove no exception crosses the callback and the
  original exception is rethrown afterward.
- **Effort:** Small to medium.
- **Tracking:** bug-ready title `Tag metadata callback can unwind across Rust FFI`;
  proposed **Should / High**.

### CR-FOO-03 — High: OpusTags import has no resource budget

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\ropus-fb2k\src\reader.rs:335`,
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\ropus-fb2k\src\tags.rs:105`, and
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\src\input_ropus_opus.cpp:126`.
- **Evidence:** open materializes the complete, possibly multi-page OpusTags
  packet. Parsing then owns vendor, key, and value strings for every real
  comment. The C++ adapter copies retained tags again into host metadata. No
  byte, comment-count, or aggregate-text budget bounds automatic library scans.
- **Actual:** a valid metadata-heavy file can amplify modest input into many
  allocations and exhaust the host during indexing. This is not the previously
  refuted fake-count capacity bomb: packet bounds prevent out-of-bounds slicing
  and the initial vector capacity is capped. The confirmed issue is real,
  attacker-supplied metadata retained without a resource ceiling.
- **Concrete fix:** impose conservative total packet-byte, comment-count, and
  aggregate retained-text limits before ownership and callback expansion.
  Enforce the byte budget while assembling the first two Ogg packets so a
  post-allocation length check is not the only guard.
- **Regression oracle:** synthesize at-limit and one-over-limit OpusTags for
  bytes and count. Require bounded allocation and `INVALID_STREAM` beyond the
  budget while normal multi-value tags still import.
- **Effort:** Medium.
- **Tracking:** bug-ready title `OpusTags import has no resource budget`;
  proposed **Should / High**.

### CR-FOO-04 — Medium: nominal bitrate rounding can overflow signed `int`

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\src\input_ropus_opus.cpp:215`;
  producer contract at
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\ropus-fb2k\src\reader.rs:1081`.
- **Evidence:** `(m_info.nominal_bitrate + 500)` is evaluated as signed 32-bit
  arithmetic before assignment to `t_int64`. The Rust producer deliberately
  clamps an extreme computed bitrate to `i32::MAX`, so the adapter can evaluate
  `i32::MAX + 500` on crafted short, metadata-heavy input.
- **Actual:** untrusted container metadata can trigger signed-overflow undefined
  behavior while the adapter formats an informational bitrate.
- **Concrete fix:** widen before arithmetic:
  `(static_cast<t_int64>(m_info.nominal_bitrate) + 500) / 1000`.
- **Regression oracle:** pass `i32::MAX`, the rounding thresholds, zero, and the
  unknown sentinel through a pure conversion helper.
- **Effort:** Trivial.
- **Tracking:** bug-ready title `Nominal bitrate rounding overflows at i32 maximum`;
  proposed **Should / Medium**.

### CR-FOO-05 — Medium: huge finite seek times reach an undefined conversion

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\src\input_ropus_opus.cpp:347`.
- **Evidence:** `decode_seek()` rejects non-finite and negative seconds but does
  not bound a huge finite value before multiplying by the sample rate. The
  product can become infinity or exceed `uint64_t`; casting it is undefined
  before the Rust backend can apply its documented clamp.
- **Actual:** an extreme host seek, including one derived from a crafted enormous
  granule duration, can trigger C++ undefined behavior.
- **Concrete fix:** clamp directly to known `total_samples` when available.
  Otherwise compare the floating value against the `uint64_t` limit before
  multiplication and casting.
- **Regression oracle:** cover negative, NaN, both infinities, the largest safe
  finite seconds, and the next larger finite value under a UB-capable C++ check.
- **Effort:** Small.
- **Tracking:** bug-ready title `Large finite seek times trigger undefined integer conversion`;
  proposed **Should / Medium**.

### CR-FOO-06 — Low: packaging removes the last good archive too early

- **Confidence:** High.
- **Location:**
  `C:\worktrees\ropus\20260802-REV-ROP-CLA@CRUCIBLE-code-review-061944\foo_ropus\build.ps1:108`.
- **Evidence:** the script deletes an existing
  `foo_ropus.fb2k-component` before `Compress-Archive` and `Rename-Item` have
  produced its replacement.
- **Actual:** compression or rename failure leaves no distributable even when
  the caller did not request `-Clean`.
- **Concrete fix:** create and validate a uniquely named same-directory
  temporary archive, then atomically replace the final archive only after every
  preceding step succeeds.
- **Regression oracle:** inject a compression failure and prove a sentinel final
  archive remains unchanged; also inspect the successful archive for exactly
  `x64/foo_ropus.dll`.
- **Effort:** Small.
- **Tracking:** bug-ready title `Packaging deletes the last good component before replacement succeeds`;
  proposed **Could / Low**.

## Not reported

### Refuted

- The stereo PCM buffer is not undersized. The backend accepts only one or two
  channels and caps a packet at 5,760 samples per channel.
- The size callback's `-1` result intentionally means unknown size in the C ABI;
  it is not independently a fatal open error.
- A large read count cannot overrun Rust through the return value: the adapter
  conversion is bounded and `CallbackReader` rejects a count above its buffer.
- Cargo running on every CMake build is an explicit, measured tradeoff to avoid
  stale static libraries.
- SDK source globs and hard-coded native library lists are fragile, but this pass
  confirmed no current omitted translation unit or silent link defect.

### Unverified

- A failed late seek may make backend recovery replay a long consumed prefix.
  The source path exists, but reuse of the same foobar2000 input instance after
  the relevant cancellation/failure was not verified. Hold for a later backend
  pass rather than filing from this adapter review.
- Metadata insertion may be quadratic with many unique keys, but the exact
  SDK-2025 implementation is absent. An older mirror is not enough to confirm
  the deployed behavior.
- Rendering untrusted tag values may permit terminal or bidi spoofing, but the
  unavailable host rendering contract decides where escaping belongs.
