# Code review: `harness-control/`

**Date:** 2026-08-16

**Baseline:** `origin/main` at `a97b6f11aaf63e502c9faaf1a3766b9bad071056`

**Method:** Static, read-only multi-lens review of every file under `harness-control/`, plus the directly invoked fixed/float decoder sources, live tier-2 oracle, integration policy, build-script asset gates, history, and existing ledgers where needed to verify contracts and deduplicate findings. Correctness, security, performance/scale, reliability, maintainability, and test-coverage lenses were challenged by a separate devil's advocate. No application, build, test, decoder, subprocess, benchmark, fuzz command, or exploratory harness ran.

## Result

Four Medium defects were independently confirmed and filed Open. The highest-confidence correctness defect is a stale loss pattern: the control drops 14 packets through frame 98 while the live tier-2 oracle drops 13 through frame 91 to preserve a complete recovery horizon. The other defects can make the control hang, race, or accept incomplete lossless output. One Heavy Draft requirement captures the duplicated fixture contract that caused the drift.

## Confirmed defects

### Medium — ROP-BUG-KILN-00016: classical control uses a stale packet-loss recovery horizon

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-control\tests\control_snr.rs:65` claims byte-identical tier-2 conditions, but `:66-68` loses every positive multiple of seven and `:303-306` expects 14 losses through frame 98. `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-deep-plc\tests\tier2_snr.rs:42-53` requires a complete seven-frame recovery horizon; `:56-66` pins 13 losses through frame 91. Git history shows the tier-2 horizon landed on 2026-08-01 while the control predicate remained unchanged from April.
- **Impact:** The final control loss ends mid-cycle, so its aggregate classical SNR no longer measures the packet/recovery scenario it claims to mirror. Phase-sensitive recovery output can distort the diagnostic comparison.
- **Concrete fix:** Share the interval and complete-cycle predicate, or copy the horizon guard exactly; assert the exact loss indexes rather than a self-derived count.
- **Effort:** Small, about 1–2 hours including a focused regression oracle.

### Medium — ROP-BUG-KILN-00017: concurrent control tests race through shared artifact paths

- **Confidence:** High.
- **Evidence:** `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-control\tests\control_snr.rs:232-237` always uses `target/harness-control-tmp`. The lossy case reuses fixed packet and PCM names at `:321-334`; the lossless case does the same at `:422-428`.
- **Impact:** Two `cargo test` processes in one checkout can truncate or read the same files while the other validates, decodes, or measures them. This can corrupt inputs, expose partial PCM, or create false failures. Separate worktrees reduce frequency but do not make one checkout process-safe.
- **Concrete fix:** Give each test invocation a unique temporary directory, clean it on drop, and add an overlapping-invocation path-isolation oracle.
- **Effort:** Small, about 1–3 hours.

### Medium — ROP-BUG-KILN-00018: decoder subprocesses have no execution deadline

- **Confidence:** High for the source defect; no hang was executed.
- **Evidence:** `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-control\tests\control_snr.rs:245-260` runs nested Cargo and decoder processes through `Command::output()` without a deadline, polling, termination, or descendant cleanup. `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\.deltic-integrate.toml:101-108` includes this package in its component gate.
- **Impact:** A Cargo lock, build, or C decoder hang can wedge a direct control test indefinitely instead of returning a bounded failure. Killing only the immediate Cargo process would not reliably reap its decoder descendants on Windows.
- **Concrete fix:** Use a cross-platform timeout-aware supervisor that terminates and reaps the process tree, returns a distinct timeout result, and has a hanging-child regression oracle.
- **Effort:** Medium, about 1–2 days including Windows and Unix cleanup tests.
- **Dedup boundary:** `ROP-BUG-CRUCIBLE-00006` covers `full-test/src/process_capture.rs` and the full-test runner. It does not bound direct `harness-control` execution.

### Medium — ROP-BUG-KILN-00019: lossless control accepts incomplete matching PCM outputs

- **Confidence:** High as an oracle gap.
- **Evidence:** The lossy path requires exactly `TOTAL_FRAMES * FRAME_SIZE * CHANNELS` samples at `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-control\tests\control_snr.rs:357-369`. The lossless path at `:450-479` checks only equal child lengths, energy, divergence, and SNR. Equal nonempty truncated prefixes can satisfy every assertion.
- **Impact:** A shared early-success or publication regression in the child decoders can be false-green in the lossless control, despite missing audio.
- **Concrete fix:** Apply one exact output-length validator to both paths; assert packet count and input frame alignment; check packet non-emptiness directly.
- **Effort:** Tiny to small, under 2 hours.
- **History:** Closed `ROP-BUG-FLUX-00033` says this validator landed, but its fix commit `b05bb88` did not modify `harness-control/`; the residual gap therefore has a new record rather than rewriting the closed entry.

## Tracked design debt

- **ROP-REQ-KILN-00020 — Centralize the shared PLC control fixture and loss policy.** `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-control\tests\control_snr.rs:46-91` and `D:\worktrees\ropus\20260816-REV-ROP-CDX@KILN-code-review-082255\harness-deep-plc\tests\tier2_snr.rs:29-94` duplicate the deterministic PCM, codec constants, and loss policy. The frame-98 drift proves the maintenance cost. The Draft is deliberately narrow: share only the scenario these two tests claim is identical; keep intentionally different diagnostics local and named.

## Not reported as new bugs

- **Missing reference assets — refuted as a false-green defect.** The sibling wrappers exit nonzero with a fetch-assets hint when the C source or weights are absent, and the control asserts child success. The repository documents those assets as a prerequisite. A fresh checkout therefore fails closed; silently skipping would make the oracle unverified. A future self-provisioning gate may improve usability, but no passing-without-evidence path exists.
- **Matching truncated lossless output is not produced by the current children — scope clarified.** Both current child success paths loop over every declared frame and propagate write/flush failure. `ROP-BUG-KILN-00019` is filed because the parent oracle does not verify its claimed invariant and would miss a shared child regression, not because static review found current children already returning truncated success.
- **Unpinned C reference — deduplicated.** The validation-integrity problem is already Open as `ROP-BUG-KILN-00007`; this pass did not file another record.
- **Fixed decoder aliasing, child input TOCTOU, and partial child artifacts — held for the relevant `harness/` or `harness-deep-plc/` area pass.** Those issues live outside the assigned directory and are not exercised by the parent's intended distinct paths. The parent-side concurrent-path trigger is fully captured by `ROP-BUG-KILN-00017`.
- **Nested release builds and full DNN/DRED compilation — report-only performance debt.** The cost is explicit in the test's design, and this read-only pass produced no timing evidence or release-budget breach. A measured threshold should precede structural work.
- **Unbounded captured stderr — not promoted separately.** The current fixed-duration children emit bounded diagnostics in ordinary operation. The broader process-lifetime correction in `ROP-BUG-KILN-00018` should choose an explicitly bounded capture policy, but this pass did not establish an independent memory failure.
- **Command injection — refuted.** Package names and binary names are literals, and paths are passed as separate `Command` arguments without a shell.
- **Packet-size and PCM buffering overflow — refuted for this fixture.** The parent generates 100 mono frames and reads about 192 KiB per decoder; both child parsers enforce packet, frame, and output caps.
