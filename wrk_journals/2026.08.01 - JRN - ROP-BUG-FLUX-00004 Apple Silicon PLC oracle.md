# ROP-BUG-FLUX-00004 — Apple Silicon PLC oracle

The 2-second DEEP_PLC differential reproduced on Apple Silicon at 35.97 dB,
below its unchanged 50 dB gate. The lossless control remained 90.14 dB.

Two harness assumptions caused the failure:

- `harness-deep-plc/build.rs` excluded platform-specific DNN source files but
  `reference/dnn/vec.h` still selected header-only NEON kernels. The Rust DNN
  port uses scalar evaluation order on AArch64. Forcing scalar C made the first
  loss bit-exact and made the RDOVAE differentials bit-exact.
- The loss pattern scheduled a final loss at frame 98 of 100, then stopped one
  frame into a normally seven-frame loss/recovery cycle. Tiny expected float
  drift in the recurrent generator amplified at that truncated final event.
  Before it, scalar C versus Rust measured 52.23 dB; both full outputs had the
  same signal-quality score against the input to two decimal places.

The fix defines `DISABLE_NEON` for the AArch64 C reference path and schedules
only losses with a complete seven-frame recovery horizon. It retains the
50 dB threshold and 13 deterministic loss events. The full
`ropus-harness-deep-plc` package passes, including its DRED and RDOVAE
differentials.
