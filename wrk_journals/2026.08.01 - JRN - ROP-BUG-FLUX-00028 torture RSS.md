# 2026-08-01 — ROP-BUG-FLUX-00028 torture RSS

## Observation

`cmd_torture` sampled RSS before allocating a full duration of PCM and again
before destroying the codecs. The default 1,800-second input therefore added
hundreds of megabytes to the reported delta even when codec state was stable.

## Fix

`harness/src/cli.rs:NoiseGenerator` now fills one bounded frame buffer per
iteration, preserving the existing deterministic sample stream without a
duration-sized allocation. The RSS baseline is captured after codec/config and
buffer setup, then the C and Rust codecs plus all reusable buffers are destroyed
before the end sample. `rss_growth_exceeds_threshold` keeps the 50 MiB warning
rule pure and testable, including shrink and exact-threshold cases.

## Validation

- `cargo fmt --check`
- `cargo clippy -p ropus-harness --bin ropus-compare --locked -- -D warnings`
- focused generator and RSS-classifier tests
- `cargo run -p ropus-harness --bin ropus-compare -- torture --duration 2 --sample-rate 8000 --channels 1 --burst-interval 0 --state-check-interval 0`

The focused tests and two-second torture smoke passed. The host did not expose
RSS through the platform probe, so that smoke reported no RSS line.
