# ROP-BUG-FLUX-00062 — output controls

## Outcome

The four CLIs now apply output policy after typed argument parsing. `ropusenc`
and `ropusdec` pass a shared quiet policy into their command reporters, so
quiet success paths emit no progress text while failures still reach the
common error handler. `ropusinfo` keeps its intentional banner-only quiet
meaning, and typed query mode remains authoritative.

Each CLI chooses Clap's `ColorChoice::Never` when the standalone `--no-color`
flag appears before `--`, which covers help and parse errors even on a TTY.
`ropusplay --list-devices` parses before printing its banner, and its
carriage-return/erase repainting now runs only on the interactive TTY path.

## Evidence

- `cargo test -p ropus-tools-core -p ropusenc -p ropusdec -p ropusinfo -p ropusplay --tests` — 133 core unit tests, 4 build-provenance tests, 22 round-trip tests, and all CLI tests passed.
- `cargo clippy -p ropus-tools-core -p ropusenc -p ropusdec -p ropusinfo -p ropusplay --tests -- -D warnings` — passed.
- `git diff --check` — passed.

The workspace still emits the expected warning that optional `reference/dnn`
weights are absent; it is unrelated to output controls.
