# ROP-BUG-FLUX-00011 — multistream frame duration validation

Static inspection found that `OpusMSEncoder::set_expert_frame_duration` stored every value without validation or a status result. The single-stream setter accepts only `OPUS_FRAMESIZE_ARG` or the defined 2.5–120 ms values. The C multistream CTL also discarded the setter result and always returned `OPUS_OK`.

The regression set a valid 20 ms duration, then passed values just below and above the accepted range. Before the fix, invalid values replaced the valid state. The setter now returns `OPUS_BAD_ARG` without mutation, and the C CTL forwards its result.

Validation:

- `deltic timeout 600 cargo test -p ropus encoder_expert_frame_duration_rejects_invalid_values --locked </dev/null` — failed before the fix, then passed after it.
- `deltic timeout 600 cargo test -p ropus multistream --locked </dev/null` — 129 passed.
- `deltic timeout 600 cargo test -p capi --locked </dev/null` — 1 unit test and doctest check passed.
- `deltic timeout 900 cargo test -p ropus --lib --locked </dev/null` — 1881 passed.
- `cargo clippy -p ropus --all-targets --locked -- -D warnings`, `cargo fmt --all -- --check`, and `git diff --check` — passed.
