# ROP-BUG-FLUX-00068 — Float decoder FFI bounds

`CRefFloatDecoder::decode` passed a safe Rust slice to `opus_decode` without
proving that it held `frame_size * channels` samples. The wrapper did not retain
the channel count, cast packet lengths directly to `opus_int32`, and allowed
non-positive frame sizes. Its diagnostic peek methods cast signed counts to
`usize` before allocation and passed unchecked offsets into C private-state
arrays.

The wrapper now retains the validated channel count and caches three capacities
reported by the pinned C decoder at construction: CELT decode memory, CELT
energy history, and SILK output history. It rejects invalid channels,
non-positive frame sizes, short output slices, packet-length conversion failure,
negative or empty peek counts, overflow, and ranges past those capacities before
calling C. Peek methods return `Result`, and their raw FFI symbols are private.
The C shims also validate every range before copying as defense in depth.

Regression tests construct a deliberately null decoder with valid cached
metadata. Invalid safe calls return `OPUS_BAD_ARG`; any accidental C entry would
dereference null and fail, so the tests pin the pre-FFI ordering. Pure helpers
also cover packet-length conversion and every range boundary.

Evidence:

- `cargo test -p ropus-harness-deep-plc --lib --locked`: 6 passed.
- `cargo test -p ropus-harness-deep-plc --test state_divergence --locked`: 3 passed.
- `cargo clippy -p ropus-harness-deep-plc --all-targets --locked -- -D warnings`: passed.

Focused review found three items and all were applied: private raw peek symbols,
cleanup of a rare non-null/error constructor result, and centralized capacity
constants. No findings were skipped or disputed.
