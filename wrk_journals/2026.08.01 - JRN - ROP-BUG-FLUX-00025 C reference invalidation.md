# ROP-BUG-FLUX-00025 — C reference invalidation

Both harness build scripts compiled large pinned C source sets but watched only a few vendor files. After an initial `cargo check -p ropus-harness`, touching `reference/src/opus_encoder.c` left the package `Fresh`, proving that Cargo could reuse stale `libopus_ref` objects.

The fixed and float harnesses now construct a validated `ReferenceBuildManifest`. Its single source list drives both `cc::Build` inputs and one file-level Cargo watch per compiled source. Recursive watches on `include`, `celt`, `silk`, `src`, and `dnn` cover headers and newly added files without watching the nested reference checkout's `.git` metadata. Local C shims also use one compile/watch registration path.

The float harness's copied `estimate_dred_bitrate` / `compute_dred_bitrate` oracle remains necessary because the vendor functions are static. The build now fingerprints the live `reference/src/opus_encoder.c` source block. A vendor change fails with an instruction to audit the local copy before accepting a new fingerprint.

Evidence:

- Before the fix, touching `reference/src/opus_encoder.c` produced `Fresh ropus-harness`.
- After the fix, the same source timestamp change marked both `ropus-harness` and `ropus-harness-deep-plc` dirty and rebuilt them.
- Touching `reference/include/opus.h` marked both harnesses dirty through their `include` directory watch.
- A temporary line inside the vendor bitrate block stopped the float build with the stale-copy audit message; removing only that probe restored the build.
- `cargo test -p ropus-harness --lib`: 6 passed.
- `cargo test -p ropus-harness-deep-plc --test dred_compute_bitrate_ffi_diff`: 2 passed.
- `cargo clippy -p ropus-harness -p ropus-harness-deep-plc --lib --locked -- -D warnings`: passed.

The first integration attempt correctly rebuilt the native AArch64 C oracle and
exposed the separately tracked ROP-BUG-FLUX-00004 DEEP_PLC failure. This branch
was held while that prerequisite landed at `1c8b95c`. After rebasing onto it,
the combined tree retained both the manifest invalidation fix and the scalar ARM
oracle. `cargo test -p ropus-harness --lib` passed all 6 manifest/fingerprint
tests, and `cargo test -p ropus-harness-deep-plc --test tier2_snr` passed all 3
tests at 52.21 dB for the neural loss path.

The pinned reference checkout and downloaded model sources remain ignored validation assets and are not part of the commit.
