# ROP-BUG-FLUX-00048 — Public command option validation

## What changed

- Added pre-I/O validation for `EncodeOptions`: explicit frame duration, complexity `0..=10`, nonzero bitrate within libopus's signed range, and expected loss `0..=100`.
- Replaced the `FrameDuration::Argument` panic with a returned error.
- Centralized checked decoder gain conversion and Q8 addition; `DecodeOptions` now rejects unrepresentable gain and packet-loss values before opening input or output.
- Added finite volume validation to `commands::play`; playback and decoder gain boundaries now reject the unrepresentable `+128 dB` value.
- Added matching Clap parsers for bitrate, complexity, packet loss, gain, and volume so command-line callers receive early diagnostics.
- Added unit tests proving invalid public options fail before I/O and CLI parsers reject malformed values.

## Validation

- `cargo test -p ropus-tools-core --lib --no-default-features` — 111 passed.
- `cargo test -p ropus-tools-core --test round_trip -- --test-threads=1` — 21 passed.
- `cargo test -p ropusenc -p ropusdec -p ropusplay` — all unit and CLI tests passed (2 + 4 + 2 + 8 + 2 + 2 tests).
- `cargo clippy -p ropus-tools-core -p ropusenc -p ropusdec -p ropusplay --all-targets -- -D warnings` — clean.
- The existing `reference/dnn` warning remains unrelated to this change.
