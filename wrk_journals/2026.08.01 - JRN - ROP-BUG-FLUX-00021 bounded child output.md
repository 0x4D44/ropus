# ROP-BUG-FLUX-00021 — bounded child output

## Scope

Several `full-test` subprocess paths used `Command::output()`, which buffers
complete stdout and stderr before the old 1 MiB post-hoc cap. Long-running or
noisy tools could therefore exhaust runner memory. IETF fetch logs and
coverage JSON had similar unbounded read points.

## Change

`full-test/src/process_capture.rs` now spawns two reader threads per child and
retains at most 1 MiB per stream, preserving a prefix, tail, and truncation
marker while keeping the child status. All full-test subprocess callers use
this helper, including quality, tests, fuzz, ambisonics, benchmarks, corpus,
platform, setup, and commit metadata. IETF temp-file logs use the bounded
reader, and coverage JSON is rejected before reading when it exceeds 64 MiB.

## Validation

- `deltic timeout 300 cargo test -p full-test --bin full-test --locked </dev/null` — 236 passed.
- `deltic timeout 300 cargo check -p full-test --locked` — passed.
- `deltic timeout 300 cargo clippy -p full-test --bin full-test --locked -- -D warnings` — passed.
- `deltic timeout 120 cargo fmt -p full-test -- --check` — passed.
- `git diff --check` — passed.

The process-capture tests emit an oversized stream, verify bounded prefix/tail
retention, and verify child exit status plus both output pipes survive capture.
