# ROP-BUG-FLUX-00066 — playback output and terminal restoration

## Change

Playback previously discarded every stdout/stderr write and flush result. Its
raw-mode guard also ignored `disable_raw_mode` failures in `Drop`, so a failed
terminal restore could silently leave the user's terminal unusable.

`commands/play.rs` now routes output through a fallible `Write` seam, flushes
each emission, and propagates failures. `RawModeGuard::restore` performs the
normal cleanup explicitly and keeps the guard active when cleanup fails so the
Drop fallback retries. Playback and restore errors are combined with both
causes preserved.

## Validation

- `cargo fmt --all`
- `git diff --check`
- `cargo test -p ropus-tools-core commands::play --lib </dev/null`
- `cargo test -p ropus-tools-core --tests </dev/null`
- `cargo clippy -p ropus-tools-core --tests -- -D warnings`

The focused tests cover write failure, flush failure, explicit restore failure,
Drop retry, and simultaneous playback plus restore errors.
