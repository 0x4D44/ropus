# ROP-BUG-FLUX-00009 — projection frame-size bounds

Static inspection found that `OpusProjectionEncoder::encode` and `OpusProjectionDecoder::decode` converted the caller's signed `frame_size` to `usize` while allocating temporary PCM buffers. The underlying multistream methods reject non-positive sizes, but that validation happened after the wrapper allocation.

The regression passed `frame_size = -1` through both wrappers under `catch_unwind`; the unpatched encoder panicked with a capacity-overflow message before returning. Both wrappers now return `OPUS_BAD_ARG` before any cast or allocation.

Validation:

- `deltic timeout 600 cargo test -p ropus test_projection_encoder_decoder_roundtrip_and_invalid_inputs --locked </dev/null` — failed before the fix with capacity overflow, then passed after it.
- `deltic timeout 600 cargo test -p ropus projection --locked </dev/null` — 5 passed.
- `deltic timeout 900 cargo test -p ropus --lib --locked </dev/null` — 1879 passed.
- `cargo clippy -p ropus --all-targets --locked -- -D warnings`, `cargo fmt --all -- --check`, and `git diff --check` — passed.
