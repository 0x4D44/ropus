# 2026-08-01 — ROP-BUG-FLUX-00031 CLI numeric validation

## Observation

The CLI parsed every numeric option as an unrestricted `i32`, then cast
iterations and scheduling intervals to unsigned types. Negative values became
huge workloads, zero change intervals reached modulo operations, and invalid
sample rates or channels reached codec arithmetic.

## Fix

Added typed command validators for Opus bitrates, complexity, application and
signal values, packet-loss percentage, iterations, durations, rates, channels,
and torture intervals. Durations and iterations are bounded; required change
intervals reject zero; burst and state-check intervals accept only zero as the
documented disable value or a bounded positive interval. Longsoak and torture
now use checked sample-count arithmetic with explicit caps before allocation or
the streaming loop starts.

## Validation

- `cargo fmt --all -- --check`
- `cargo clippy -p ropus-harness --bin ropus-compare --locked -- -D warnings`
- `cargo test -p ropus-harness --bin ropus-compare --locked` (15 tests passed)
- invalid CLI smoke tests for negative iterations, zero change interval, zero
  sample rate, and three channels all exited 1 before workload setup
- one-second torture smoke with zero burst/state intervals passed
