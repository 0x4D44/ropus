# ROP-BUG-FLUX-00022 — projection gate frame proof

The projection parity gate derived `total_frames` with integer division and treated zero encode/decode mismatches as success. A valid empty WAV or a fixture shorter than one 20 ms frame therefore ran neither codec but still emitted the release-consumed PASS marker.

The fix rejects inputs with no complete frame before constructing either codec. `FixtureResult` now records completed frames separately from planned frames, and `passed()` requires a nonzero completed count equal to the plan as well as zero mismatches.

Regression evidence:

- Before the fix, the empty and 3,839-of-3,840-sample cases both failed because `passed()` returned true.
- `cargo test -p ropus-harness --bin projection_roundtrip`: 4 passed.
- `cargo clippy -p ropus-harness --bin projection_roundtrip --locked -- -D warnings`: passed.
- `cargo run -p ropus-harness --bin projection_roundtrip -- tests/vectors/ambisonic/ambisonic_order1_100ms.wav`: processed five frames; encode and decode parity both passed.

The C reference checkout and model sources were fetched into ignored worktree paths for validation. They are not part of the commit.
