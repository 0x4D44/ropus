# ROP-BUG-FLUX-00055 — output identity guards

## What changed

- Added a shared platform-metadata guard for ropusenc and ropusdec. It rejects direct, lexical, symlink, and hard-link aliases before input decoding or output creation.
- Default destinations now use `*.encoded.opus` or `*.decoded.{wav,pcm}` when the source already has the requested extension, preserving content-based decode inputs named with output extensions.
- Applied the same explicit alias check to the float-reference control decoder before it validates or creates its PCM output.
- Added identity, default-suffix, and source-preservation tests, plus the direct float-harness guard.

## Evidence

- `cargo test -p ropus-tools-core --lib --no-default-features` — 128 passed.
- `cargo clippy -p ropus-tools-core -p ropus-harness -p ropus-harness-deep-plc --all-targets -- -D warnings` — clean.
- `cargo check -p ropus-tools-core -p ropus-harness -p ropus-harness-deep-plc` — clean.

The harness test binaries report zero tests in this checkout because the optional
reference C tree is absent; the new inner-module tests compile when that reference
is provisioned.
