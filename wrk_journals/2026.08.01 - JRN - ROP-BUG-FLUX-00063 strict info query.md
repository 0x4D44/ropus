# ROP-BUG-FLUX-00063 — strict info query integrity

## Outcome

`ropusinfo --query duration` and `--query bitrate` now fail when the unknown
granule fallback cannot decode an Opus packet. The decoder error returns
through the normal CLI error path before either query emits a scalar. Fast
granule queries validate the target stream's packets before trusting the
granule.

Human-readable info keeps its diagnostic fallback, but carries an explicit
`SampleCount::Estimate` state and labels both playback length and average
bitrate with the number of skipped packet errors.

## Evidence

- `cargo test -p ropus-tools-core -p ropusinfo --tests` — 133 core unit tests, 4 build-provenance tests, 22 round-trip tests, and 8 ropusinfo CLI tests passed.
- `cargo clippy -p ropus-tools-core -p ropusinfo --tests -- -D warnings` — passed.
- The CLI regression builds CRC-valid Ogg pages with an unknown EOS granule and a non-empty invalid Opus packet; both strict queries fail with empty stdout.

The workspace still emits the expected warning that optional `reference/dnn`
weights are absent; it is unrelated to query integrity.
