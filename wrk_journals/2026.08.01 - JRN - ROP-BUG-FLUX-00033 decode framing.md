# ROP-BUG-FLUX-00033 — Decode framing validation

## What changed

`harness/src/cli.rs` previously let the C and Rust framed decoders stop at the
last complete packet. A valid prefix followed by one length byte or an
incomplete payload therefore reached the sample comparison and could report a
pass. The `decode` command now parses its two-byte little-endian framing once
with `parse_framed_packets`, rejects every non-boundary EOF, and sends the same
borrowed packet list to both decoders. Decoder construction and packet errors
now return `CompareCommandOutcome::Fail` instead of exiting after partial PCM.

The older permissive `parse_packets` helper remains for diagnostic commands
that intentionally inspect partial streams; the user-facing `decode` path uses
the strict parser.

## Regression coverage

`cli_validation_tests` covers a truncated length after a valid packet, a
truncated payload after a valid packet, and the command-level `Fail` outcome
before any decoder comparison.
