# ROP-BUG-FLUX-00060 — picture output safety

## Outcome

`ropus-tools-core::commands::encode` now prepares `--picture` metadata before any
destination mutation. It opens the picture once and reads at most
`MAX_PICTURE_BYTES + 1`, so growth or a stale size query cannot bypass the cap.
The output path is rejected when it aliases either the audio input or picture,
including direct, symlink, and hard-link identities.

Regular-file encoding writes to a unique temporary beside the destination and
renames it only after the Ogg writer flushes. A failed picture read or format
check therefore leaves an existing output byte-for-byte unchanged.

## Evidence

- `cargo test -p ropus-tools-core --lib commands::encode::tests` — 5 passed,
  including missing, empty, invalid, oversized, direct-alias, symlink-alias,
  and hard-link-alias preservation cases.
- `cargo test -p ropus-tools-core --test round_trip` — 22 passed, including
  picture metadata embedding over a pre-existing output sentinel.
- `cargo test -p ropusenc --test cli` — 8 passed.
- `cargo clippy -p ropus-tools-core --tests -- -D warnings` — passed.
- `cargo clippy -p ropusenc --tests -- -D warnings` — passed.

The checkout has no `reference/dnn` assets, so the normal compile warning about
the optional neural PLC blob remains expected and unrelated to this fix.
