# ROP-BUG-FLUX-00006: fuzz reference provisioning

The fuzz crate's `build.rs` requires `reference/celt/bands.c`, but `reference/`
is ignored and absent in a clean task worktree. Reproduction failed at the
custom build step with `Reference opus source not found`, even though the
repository already carries the pinned, idempotent `fetch-assets reference`
provisioner.

The `harness` and `fuzz` integration components now run
`cargo run -p fetch-assets --locked -- reference` immediately before their
fuzz-manifest check. A clean gate provisions the exact pinned xiph/opus commit;
an existing checkout is detected and skipped. This keeps the focused gate
reproducible without committing the large ignored reference tree.

Validation from a clean task worktree:

- The provisioner cloned and checked out the pinned reference successfully.
- `cargo fmt --all -- --check` passed.
- The nested fuzz formatter check passed.
- `cargo check --manifest-path tests/fuzz/Cargo.toml --locked` passed.
- `deltic integrate-config validate --json` passed, and the fuzz explanation
  showed provisioning before the manifest check.
