# ROP-BUG-FLUX-00013 — Extension parser bounds

## Finding

Static inspection of the safe extension APIs found that `opus_packet_extensions_parse` used `nb_extensions` as an indexing bound without checking `extensions.len()`. `opus_packet_extensions_parse_ext` accepted negative or overflowing per-frame counts and could cast a negative prefix index to `usize`. The iterator also trusted a declared `len` beyond the input slice.

## Reproduction

Added focused regressions for a short parse output slice, negative per-frame counts, a short parse-ext output slice, declared output-capacity shortage, and an iterator length larger than its input. Before the fix, the short parse slice panicked at `repacketizer.rs:675`; the negative count silently returned success; and the iterator length test returned an extension instead of rejecting the input.

## Fix

The parser entry points now reject invalid frame counts, input lengths beyond the safe slice, negative capacities, and capacities larger than their output slices. The per-frame parser builds its placement prefix with checked non-negative arithmetic and validates indices before scattering. The iterator records inconsistent lengths or frame counts as an invalid state, so `next_ext` returns `OPUS_INVALID_PACKET` without indexing past the slice.
