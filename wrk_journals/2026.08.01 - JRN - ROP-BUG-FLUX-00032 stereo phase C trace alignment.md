# ROP-BUG-FLUX-00032 — Stereo Phase-C trace alignment

## What changed

`harness/src/bin_inner/fuzz_repro_diff.rs` previously keyed Phase-C tuples only by
`(boundary_id, iter)` before collecting them into `BTreeMap`s. Stereo traces emit
multiple records for those logical keys, so each map kept only the last channel
record. The matcher now assigns a trace-order occurrence ordinal within each
`(boundary_id, iter)` group and keys records by `(boundary_id, iter, occurrence)`.
Diagnostics include the occurrence and both channel labels; when Rust retains its
`-1` sentinel, the C channel is used in the first-divergence summary.

## Regression coverage

The `phase_c_key_tests::occurrence_keys_preserve_stereo_records_and_first_divergence`
unit test builds two-channel synthetic traces. It verifies both occurrences remain
in each map, a payload mismatch in the first occurrence is visible, the second
occurrence still matches, and C channel labels remain attached to their records.
