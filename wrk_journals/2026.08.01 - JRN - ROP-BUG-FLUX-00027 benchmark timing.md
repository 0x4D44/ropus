# 2026-08-01 — ROP-BUG-FLUX-00027 benchmark timing

## Observation

The C encoder and decoder benchmark timers started before `opus_*_create` and
stopped after `opus_*_destroy`. Rust construction and configuration were already
outside the timed interval, so the comparison used asymmetric lifecycle costs.

## Fix

`harness/src/cli.rs:timed_c_lifecycle` now owns the shared C benchmark sequence:
construct, configure, start the timer, run the measured work, stop the timer,
then destroy. The C encoder validates construction and all benchmark CTLs before
the timer starts. An injected timer test records all six lifecycle events and
asserts that only the work interval is measured.

## Validation

- `cargo fmt --check`
- `cargo test -p ropus-harness --bin ropus-compare c_benchmark_lifecycle_times_only_work --locked`

The focused test passed. The integration gate will run the complete harness
suite and the C reference checks.
