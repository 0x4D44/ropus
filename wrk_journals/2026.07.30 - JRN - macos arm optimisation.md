# 2026-07-30 — macOS / ARM optimisation

## Goal

Make macOS on Apple Silicon a measured, bit-exact performance target:

- build the C comparison oracle correctly on AArch64;
- use a conservative Apple-Silicon compiler baseline;
- profile the fixed-point codec on Apple Silicon;
- complete only the safe SIMD kernels justified by evidence;
- preserve identical codec output and the existing cross-platform fallback.

Raw `std::arch::aarch64` intrinsics, a new dependency, internal codec
threading, and floating-point reassociation are out of scope unless the
evidence exposes a blocker that cannot be solved through the existing `wide`
dependency or compiler-friendly safe Rust.

## Compiler baseline and profiling

Five alternating whole-codec A/B pairs compared separately built generic
AArch64 and `apple-a14` artifacts on `music_48k_stereo.wav`. A14 won encode
and combined encode/decode in all five pairs. The median combined gain was
about 3–4%; decode alone was close to noise. A fixed-serial 64 kb/s CBR
encode produced the same SHA-256 on both builds:
`e68fe64a3f1f78fd8953bbdc43f66b934832ec9e3092ffc41724d503f46e9194`.
The exact `aarch64-apple-darwin` target setting was therefore retained.

A symbolised, unstripped `apple-a14` profile used macOS `sample` against the
actual `ropusenc` child process:

- music encode: `celt_encode_core`, `op_pvq_search`, `celt_pitch_xcorr`,
  `exp_rotation1`, `opus_fft_impl`, and `compute_mdcts` dominated;
- speech encode: `silk_nsq_del_dec` and
  `silk_warped_autocorrelation` dominated.

The SILK delayed-decision quantizer is recursive stateful code. Upstream's
warped-autocorrelation NEON implementation is a transposed recurrence rather
than a small lane-wise translation. Neither was suitable for a lean safe-SIMD
patch. Generated AArch64 for the existing CELT pitch correlation contains
`ldp q`, `mla.4s`, and `addv.4s`, proving the retained portable path lowers to
NEON.

## SIMD candidate results

Each candidate started with scalar-oracle tests, then ran five alternating
focused release A/B pairs:

- CELT single/dual inner products: safe `wide::i32x4` matched wrapping and
  truncation semantics, but was roughly 50% slower and lost 5/5.
- FFT downshift: packing two complex values into `i32x4` was bit-exact, but
  was roughly twice as slow and lost 5/5.
- MDCT window multiply: an exhaustive coefficient/residue proof and existing
  vector tests passed, but the full window kernel lost 5/5 by a wide margin.

All three prototypes were removed. The only codec-source edit retained is a
correction to the stale module comment that claimed SIMD was feature-gated.
The final simplicity pass also removed `NSQ_del_dec_neon_intr.c` from both C
source manifests because the safe no-RTCD macro set cannot select it.
