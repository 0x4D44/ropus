# ROP-BUG-FLUX-00053: typed banner routing

The shared prelude guessed input and output positions by scanning raw arguments
without knowing each option's arity. For example, `ropusenc --bitrate 64000 -`
mistook `64000` for the input and printed its banner before the Ogg stream.
`ropusdec --rate 44100 -` similarly prefixed WAV output, while
`ropusinfo -q=duration` prefixed its scalar result because the scanner did not
recognise Clap's attached short value.

The four binaries now parse once with Clap before choosing banner behaviour.
Encoder and decoder routing uses their typed input and output paths. Info query
mode uses the typed query field. The shared prelude now owns only typed stdout
routing, colour configuration, and error-to-exit handling.

Regression tests first failed with ASCII banner bytes where `OggS` or `RIFF`
was required, and with two info output lines instead of one. After the fix:

- `cargo test -p ropus-tools-core --lib --locked` passed 96 tests.
- `cargo test -p ropusenc -p ropusdec -p ropusinfo -p ropusplay --all-targets --locked` passed all 25 tests.
- Strict Clippy passed for the shared tools crate and all four CLI packages.
- `cargo fmt --all -- --check` and `git diff --check` passed.

The build emitted the existing warning that optional DNN weight assets are not
present in this worktree. It did not affect these CLI tests.
