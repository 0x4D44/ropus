# 2026-08-01 — ROP-BUG-FLUX-00030 WAV reader bounds

## Observation

The CLI, projection roundtrip, and PCM drift binaries each parsed RIFF chunks
independently. They indexed fixed `fmt ` fields and declared `data` extents
before proving that either chunk fit in the file, so malformed WAV input could
panic and the three callers accepted different malformed files.

## Fix

Added `ropus_harness::wav::parse_pcm16_wav`, a fallible PCM16 RIFF/WAVE parser.
It checks RIFF extents, chunk headers, padded chunk ends, PCM format, nonzero
rate and channels, byte rate, block alignment, and complete sample alignment.
The three callers now use the shared parser and turn errors into a controlled
nonzero exit.

## Validation

- `cargo fmt --all -- --check`
- shared parser unit tests for valid input, truncated `fmt `, oversized
  `data`, zero channels, and odd sample alignment
- `cargo clippy -p ropus-harness --all-targets --locked -- -D warnings`
- `cargo run -p ropus-harness --bin projection_roundtrip -- tests/vectors/ambisonic/ambisonic_order1_100ms.wav --bitrate 64000`
- `cargo run -p ropus-harness --bin ropus-compare -- encode tests/vectors/48000hz_mono_noise.wav`
