# ROP-BUG-FLUX-00005: nested fuzz rustfmt gate

The root workspace excludes `tests/fuzz`, which has its own Cargo workspace.
The fuzz component nevertheless ran only `cargo fmt --all -- --check`, so a
formatting error in a fuzz target could pass the selected integration gate.
The direct nested check reproduced the gap: root formatting passed while
`cargo fmt --manifest-path tests/fuzz/Cargo.toml -- --check` found the import
ordering in `fuzz_targets/oracle.rs`.

The fuzz component now runs both the root check and the manifest-specific fuzz
check before its existing locked Cargo check. The shared `oracle.rs` source is
included by the root edition-2024 harness and the standalone edition-2021 fuzz
workspace; those formatters choose opposite import orders. A narrowly scoped
`rustfmt::skip` keeps the shared import stable while both workspaces remain
checked.

Validation:

- `cargo fmt --all -- --check` passed.
- `cargo fmt --manifest-path tests/fuzz/Cargo.toml -- --check` passed.
- `cargo check --manifest-path tests/fuzz/Cargo.toml --locked` passed with the
  existing local reference checkout available.
- `deltic integrate-config validate --json` passed and explained the fuzz path
  as a scoped component with both formatter commands.
